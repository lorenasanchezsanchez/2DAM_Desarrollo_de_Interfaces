6.2. Hola Compose

Pots seguir la construcció amb les diapositives en PDF.

Continuem en el mateix projecte multiplataforma creat en 6.1. No crees un altre projecte ni tanques l’actual: obri la mateixa carpeta en Android Studio i treballa sobre els mateixos fitxers. Ara ampliarem el App() que ja executàvem amb una salutació petita per poder seguir cada canvi a la finestra. El punt d’entrada Android i el main() d’escriptori ja mostren App(); no els tocarem. Dins de commonMain escriurem la pantalla, que no utilitza cap servei específic d’Android.

Compose descriu la interfície com una funció que diu què s’ha de veure ara. No li diem que busque un botó per id i que canvie el seu text a mà. Quan canvien les dades d’entrada, Compose torna a executar les funcions afectades i actualitza la finestra. Això s’anomena recomposició.

Paraules que apareixen en aquesta pantalla:

  • @Composable marca una funció que pot dibuixar interfície Compose.
  • Column posa els seus elements un davall de l’altre; Row els posaria en horitzontal.
  • Text mostra una cadena. OutlinedTextField és un camp on es pot escriure i rep una funció que crida en editar-lo; Button i OutlinedButton responen a un clic.
  • Modifier és una cadena d’ajustos del component. fillMaxSize() ocupa l’espai disponible i padding(32.dp) deixa espai interior. dp és una unitat independent de la densitat de píxels de la pantalla.
  • MaterialTheme aplica els colors, la tipografia i les formes del tema. MaterialTheme.typography.headlineLarge selecciona un estil de títol.
  • Una lambda és una funció curta escrita al lloc on la necessitem. {} és una lambda buida: indica que el control encara no té cap acció.

Els imports de androidx.compose... donen accés als components Compose. Alguns noms encara contenen androidx perquè Compose va nàixer en Android, però aquests components estan publicats també per a Compose Multiplatform. Si Android Studio marca un nom en roig, posa el cursor damunt del nom i usa l’acció Import; no cal escriure tots els imports a mà.

Què ja coneixem i què és nou?

Primer construirem una pantalla estàtica amb components Compose i després farem que reaccione a les dades que escrivim. En aquesta pàgina anomenarem recomposició al fet que Compose torne a executar la part de la interfície que llig un estat quan aquest canvia.

Abans del primer pas. Dir-li a l’app quina pantalla mostrar

El projecte generat té un composable arrel anomenat App(). Les dues plataformes ja el criden. MaterialTheme aplica colors, tipografia i formes predeterminats als components que conté. Deixa el nom App() com està i canvia’n el contingut perquè mostre HolaCompose():

Obri shared/src/commonMain/kotlin/ i segueix les carpetes del paquet que vas triar en crear el projecte fins a trobar App.kt. Editarem aquest fitxer existent: conserva la línia package i els imports que ja necessites, i no crees un altre App() en un fitxer diferent. Android Studio pot afegir els imports de Compose quan els components apareguen en roig.

@Composable
fun App() {
    MaterialTheme {
        HolaCompose()
    }
}

HolaCompose() és la nostra funció de pantalla. Com que totes dues funcions són en commonMain, Android i Desktop arriben al mateix contingut. El punt d’entrada de cada plataforma continua sent el que ha creat l’assistent.

Pas 1. Crear la pantalla i mostrar un títol

En el mateix App.kt, davall de App(), crea HolaCompose(). Així mantens el punt d’entrada generat i afegeixes la pantalla compartida al mateix paquet. Comença amb una columna i un únic text:

@Composable
fun HolaCompose() {
    Column(Modifier.fillMaxSize().padding(32.dp)) {
        Text("Hola Compose", style = MaterialTheme.typography.headlineLarge)
    }
}

Executa Desktop i comprova que aparega el títol. Si no el veus, revisa que App() cride HolaCompose() i que el fitxer estiga en commonMain.

Pas 2. Afegir les instruccions i el camp

Afig dins de la mateixa Column, després del títol, un text d’ajuda i un camp buit. Encara no guardem el que s’escriu: value = "" i onValueChange = {} deixen el control sense comportament perquè puguem comprovar la distribució.

Text("Escriu el teu nom i prem Saludar.")
OutlinedTextField(value = "", onValueChange = {}, label = { Text("El teu nom") })

Executa de nou i comprova que el camp mostra l’etiqueta davall del text.

Pas 3. Afegir botons sense acció

Col·loca els botons en una Row davall del camp:

Row(horizontalArrangement = Arrangement.spacedBy(12.dp)) {
    Button(onClick = {}) { Text("Saludar") }
    OutlinedButton(onClick = {}) { Text("Netejar") }
}

Les lambdes buides {} indiquen que encara no hi ha cap acció. Executa Desktop i prova de prémer-los: encara no passa res, com esperem en aquesta etapa.

onClick = {} passa la lambda buida que acabem de veure. En el pas següent escriurem dins de la lambda l’acció que volem executar. onValueChange rep el text nou com a paràmetre; el component ja defineix el tipus d’acció, així que no cal declarar una funció a banda.

El camp i el botó encara no fan res. Executa Desktop i compara la finestra amb la captura. Si no compila, comprova que el composable està dins del mòdul shared i que Gradle ha acabat la sincronització.

Pas 4. Fer que el camp recorde el text

Ara necessitem que el programa recorde què escriu la persona. Una variable Kotlin sola no és suficient: Compose no sap quan ha de tornar a dibuixar la interfície. mutableStateOf crea un valor observable per Compose; remember manté eixe valor entre recomposicions mentre aquesta pantalla continua oberta. by permet llegir i assignar el valor com una variable normal. En onValueChange, it és el nom curt que Kotlin dona a l’únic paràmetre de la lambda. Podríem escriure textNou -> per posar-li un nom explícit.

Declara l’estat al principi de HolaCompose(). Després, substitueix la línia de OutlinedTextField del pas 2 per aquesta versió connectada a l’estat:

var nomEscrit by remember { mutableStateOf("") }
OutlinedTextField(
    value = nomEscrit,
    onValueChange = { nomEscrit = it },
    label = { Text("El teu nom") }
)

Escriu i esborra text. onValueChange rep el text nou (it) i l’assigna a l’estat; en tornar a dibuixar, value mostra el valor guardat. Si el camp torna a quedar buit cada vegada que escrius, comprova que el seu value siga nomEscrit, no una cadena fixa.

Pas 5. Fer que Saludar mostre un missatge

Afegim un segon estat per distingir el text escrit del nom saludat. if (condició) permet mostrar un component només quan la condició és certa; isNotEmpty() comprova que la cadena no estiga buida. Declara l’estat al principi de HolaCompose(), substitueix només el botó Saludar que ja tens dins de la Row per la versió següent i afig el Text condicional després de la Row:

var nomSaludat by remember { mutableStateOf("") }
Button(onClick = { nomSaludat = nomEscrit }) { Text("Saludar") }
if (nomSaludat.isNotEmpty()) Text("Hola, $nomSaludat!")

En prémer Saludar, el botó copia el text escrit a nomSaludat; Compose actualitza el missatge quan la condició és certa.

Pas 6. Netejar i evitar una salutació buida

trim() lleva els espais del principi i del final d’un text. isNotBlank() comprova que quede algun caràcter que no siga un espai. Substitueix els dos botons de la Row per aquestes versions: Saludar queda desactivat si no hi ha un nom útil i Netejar buida tant el camp com el missatge.

Button(onClick = { nomSaludat = nomEscrit.trim() }, enabled = nomEscrit.isNotBlank()) {
    Text("Saludar")
}
OutlinedButton(onClick = {
    nomEscrit = ""
    nomSaludat = ""
}) { Text("Netejar") }

En prémer Netejar, desapareix el missatge i es buida el camp.

No guardem el nom després de tancar l’app; per a aquesta pantalla temporal no ho necessitem. Més avant veurem una eina de persistència quan tinga sentit conservar dades. El comportament i el codi d’estat són els mateixos en Android i Desktop; només canvia qui obri la pantalla.

Comprova: escriu un nom, saluda’l, prova un camp buit i un camp amb espais, neteja i executa la mateixa pantalla en Android. Continua amb el comptador de vides.
