6.3.2. Afegir estat i transferències

Ja tenim els dos jugadors i els controls. Ara farem que el pare Comptador guarde les vides i passe a cada targeta el valor i les accions que necessita. Després connectarem les fletxes perquè una sola acció actualitze els dos jugadors.

Pas 5. Fer que un botó actualitze el marcador

Ara guardarem els valors en Comptador, el pare que dibuixa els dos jugadors. remember conserva els números mentre la finestra està oberta; mutableIntStateOf crea un estat que conté un Int i avisa Compose si canvia.

Declara aquestes variables al principi de Comptador:

var vides1 by remember { mutableIntStateOf(20) }
var vides2 by remember { mutableIntStateOf(20) }

Si Android Studio marca algun nom en roig, importa remember, mutableIntStateOf, getValue i setValue des de androidx.compose.runtime. Els dos últims imports permeten usar by amb l’estat, com ja hem fet en 6.2.

Perquè TargetaJugador puga mostrar i canviar el valor, li passarem les dades i dues funcions. Modifica només els paràmetres de la capçalera que ja tens; conserva el cos i les claus { } de la funció. Aquesta és la signatura completa dels paràmetres (el bloc no inclou el cos):

@Composable
fun TargetaJugador(
    numero: Int,
    vides: Int,
    onSumar: () -> Unit,
    onRestar: () -> Unit,
    modifier: Modifier = Modifier
)

Int és un nombre enter. () -> Unit és el tipus d’una funció que no rep cap valor i no retorna cap resultat. Ací eixa funció representa una acció per executar quan es prem un botó. A la funció filla no li diem directament com calcular el nou total: li donem accions anomenades onSumar i onRestar.

Canvia els dos botons de cor perquè criden les accions i mostra vides en lloc del valor fix:

FilledTonalButton(
    onClick = onSumar,
    modifier = Modifier.weight(1f).fillMaxHeight()
) {
    Text("♥", color = Color.Red)
}
// En el segon botó:
FilledTonalButton(
    onClick = onRestar,
    enabled = vides > 0,
    modifier = Modifier.weight(1f).fillMaxHeight()
) {
    Text("♡", color = Color.Red)
}
// En el marcador:
Text("$vides", fontSize = 32.sp, fontWeight = FontWeight.Bold)

En la Row de Comptador, passa a cada targeta el seu valor i què ha de fer cada acció:

TargetaJugador(
    numero = 1,
    vides = vides1,
    onSumar = { vides1++ },
    onRestar = { vides1-- },
    modifier = Modifier.weight(1f)
)

TargetaJugador(
    numero = 2,
    vides = vides2,
    onSumar = { vides2++ },
    onRestar = { vides2-- },
    modifier = Modifier.weight(1f)
)

Quan es prem un cor, la targeta executa la funció rebuda. Aquesta funció canvia vides1 o vides2 al pare. Com que la variable és estat Compose, es torna a dibuixar la part que llig eixe valor i el marcador mostra el número nou. Aquest patró —el pare guarda les dades i passa accions cap avall— és una forma mínima d’estat elevat. No necessitem ara ViewModel, StateFlow ni una llibreria d’arquitectura.

Pas 6. Connectar les fletxes centrals

Les dues fletxes viuen en Comptador, perquè cadascuna canvia dos números alhora. Substitueix els seus onClick = {} per:

FilledTonalButton(
    onClick = {
        vides1++
        vides2--
    },
    enabled = vides2 > 0,
    modifier = Modifier.fillMaxWidth()
) {
    Text("P1 ← P2")
}

FilledTonalButton(
    onClick = {
        vides1--
        vides2++
    },
    enabled = vides1 > 0,
    modifier = Modifier.fillMaxWidth()
) {
    Text("P1 → P2")
}

El contingut de onClick és una lambda: instruccions que el botó executa després del clic. Els signes ++ i -- sumen i resten u. enabled desactiva una fletxa quan el jugador que perdria la vida ja està a zero; així no apareixen valors negatius. L’ordre de les fletxes del text indica quina vida es transfereix; prova les dues direccions i comprova que un marcador puja mentre l’altre baixa.
